# Wealth Primer

A financial education blog for Indian retail investors, live at <https://wealthprimer.in>. It **teaches concepts**; it does not give stock tips, predictions, target prices or personalised advice. That line is both the brand ("credibility-first") and the legal position (no SEBI Research Analyst / Investment Adviser registration needed).

Built with Jekyll on GitHub Pages. Six series (Jargon, Fundamental Analysis, Technical Analysis, Mutual Funds, Tax, Risk), one fictional case-study company (Desi Bites Foods) and a set of Claude Code skills, an agent pair and scheduled tasks that make writing, checking and shipping safer.

- Rules every post must follow: [`CLAUDE.md`](CLAUDE.md)
- What is open / decided / parked, and how the repo works: [`TODO.md`](TODO.md)
- Audits and reviews: [`_review/`](_review/)

## 1. Quick start

You don't need to memorise anything. Describe what you want in plain words in a Claude Code session in this repo; the right skill is picked from its description. Typical sentences:

| You say | What runs |
|---|---|
| "What should we write next for the tax series?" | `plan-module` |
| "Write the posts in the approved plan" | `write-post` (+ `make-chart`, `verify-claims`, then `post-auditor`) |
| "Is this circular citation right?" | `verify-claims` |
| "Audit the site" | `site-audit` |
| "What's stale?" / "update this after the Budget" | `refresh-post` |
| "Tweet for today's post" | `social-hooks` |
| "Create PR and merge" | `ship` |

Nothing is published by Claude. A post goes live on its own `date:` when the daily GitHub Pages build runs (09:00 IST). Nothing is opened, merged or tweeted unless you ask.

### Local commands

```bash
python3 scripts/check_posts.py                      # structure, data refs, charts, links: must show 0 errors
python3 .claude/skills/write-post/scripts/lint_post.py _posts/<file>   # advisory compliance lint
scripts/jekyll_build.sh /tmp/site                   # build as the live site sees it
scripts/jekyll_build.sh /tmp/site --future          # include scheduled posts (catches Liquid/link errors)
scripts/ship_check.sh                               # all pre-merge checks in one go
```

On a normal machine `bundle exec jekyll serve --future` also works. In the Claude cloud sandbox `jekyll` isn't on PATH, hence `scripts/jekyll_build.sh`.

## 2. How the content system fits together

```
 research (weekly) ──► plan-module ──► [you approve] ──► write-post ──► post-auditor ──► ship ──► daily publish
   post-researcher        roadmap          gate        (+make-chart,     fresh-eyes      PR,        09:00 IST
                                                        verify-claims,    review          merge,     GitHub Pages
                                                        refresh-data)                     verify
                                         monitor: daily go-live check · monthly site audit · yearly Budget review
                                         maintain: refresh-post · refresh-data · site-audit
```

Principles baked into every tool:

1. **Educational only.** No buy/sell/hold, targets, or soft verdicts on a real company ("cheap", "rich", "honest of them").
2. **3-month data lag** for any worked-example price or figure (house rule, stricter than SEBI's), with the as-of date shown.
3. **Numbers come from `_data/`**, generated by scripts in `scripts/`; never typed into prose.
4. **Never state a rule from memory.** Cite the primary source with number and date, or soften and say "check the current rule".
5. **Tax posts need a professional read** before publishing.
6. **Approval gates.** Roadmaps need your approval; PRs and merges need your request; reviewers report, they don't edit.

## 3. Skills

Skills live in `.claude/skills/<name>/SKILL.md`. Claude loads one automatically when your request matches its description, or you can name it ("run plan-module for risk").

### `new-series` — where does a new topic go?
- **Purpose:** decide between an existing series, a brand-new series, or the standalone bucket (`explainers`, unnumbered), and scaffold a series with `python3 scripts/new_series.py <slug> "Title" --description … --about …` (adds the `_data/series.yml` entry and the hub page; everything else follows automatically; the hub is noindexed until its first post is live; the slug is permanent).
- **Use when:** "this doesn't fit anywhere", "start a series on X".
- **Parked:** company analysis is deliberately not offered (it conflicts with the educational-only rule); the skill and research agent won't propose it.

### `plan-module` — decide what to write next
- **Purpose:** produce a roadmap (about 4–8 posts) for one series, for you to approve. Output is a table and a `TODO.md` entry, never posts.
- **Use when:** a series' written backlog is running out, or you ask "what next".
- **How:** "Run plan-module for the risk series." It reads series state, owned terms (`term:` front matter: one term, one owner), promises of "later in this series", and proposes topics, order, dates (one post per series per day), data needs, and compliance risks. It stops at an approval gate.
- **You then:** approve, edit, or reject topics. Nothing is written before that.

### `write-post` — draft, edit, audit, SEO-check
- **Purpose:** write posts to the house template (definition → formula → worked example → common mistakes → takeaway), or review/improve one.
- **Use when:** "write the posts in the approved plan", "rewrite this post", "SEO-check this draft", "audit before scheduling".
- **Files:** `references/seo.md` (title ≤ 60-char rule, descriptions, internal linking, what not to target), `audit.md` (the A–E checklist), `post-skeleton.md` (front matter, data pattern, Liquid snippets); `scripts/lint_post.py` (advisory linter: hype in title/description, forward `post_url`, list-breaking line starts, missing Takeaway, publish time after 09:00 IST, data inside the lag; WARN for trade-call and verdict words).
- **Rule of thumb:** a clean lint run is not proof of compliance. Read every sentence about a real company and ask "measurement or judgement?".

### `verify-claims` — check rules against the primary source
- **Purpose:** confirm a rule, rate, threshold or citation by opening the real document (SEBI circular, Income-tax Act text), not by memory.
- **Use when:** clearing a `VERIFY` row in `TODO.md`, before scheduling any rules or tax post, after a regulatory change.
- **How:** `python3 .claude/skills/verify-claims/scripts/fetch_source.py get <URL> --name x` then `find x "<regex>"` / `show x <line>`. Outcome per claim: confirmed, corrected, or unreachable (soften + VERIFY row). `references/sources.md` lists known URLs and what is reachable from the sandbox.
- **Limit:** doesn't replace the professional read for tax posts.

### `refresh-data` — keep datasets honest
- **Purpose:** show which datasets in `assets/data/` are stale or inside the lag window, and fetch new data when a post needs it.
- **Use when:** a new post needs a later window, a new fund or index.
- **How:** `data_status.py [--for-date YYYY-MM-DD]` (cutoff = date − 3 months, which scripts read each file), `fetch_nifty_tri.py` (NSE Indices, chunked), `fetch_nav.py` (mfapi.in; `--search` to find scheme codes). Then re-run the listed `scripts/derive_*.py`, never hand-edit `_data/`.
- **Caution:** if re-deriving changes figures in already-published posts, stop and ask.

### `refresh-post` — update a live post safely
- **Purpose:** keep published posts correct without breaking URLs.
- **Use when:** a rule changed, data was extended, Search Console shows page-2 queries, after the Budget.
- **How:** `scripts/stale_posts.py` ranks candidates (age × changeable-fact markers). Rules: never rename/delete; `last_modified_at` only for substantive changes; no forward `post_url`; numbers via scripts; tax posts go back to "pending professional read".

### `make-chart` — SVG charts in house style
- **Purpose:** one claim per chart, drawn from committed data, byte-stable, with alt text and dimensions.
- **How:** import `.claude/skills/make-chart/scripts/chartkit.py` (palette, source line, deterministic SVG) in a `scripts/make_<series>_charts.py`; output to `assets/charts/`; then `python3 scripts/add_img_dims.py`.

### `build-calculator` — Sheets / Python calculators
- **Purpose:** specify (and, only if you ask, build) a DCF, rolling-returns or SIP/XIRR calculator. Always spec first: inputs, formulas, outputs, check cases that reproduce the post's example. Does not create or share a Google Sheet unless you ask. The three owed sheets are tracked in `TODO.md`.

### `social-hooks` — one tweet per post
- **Purpose:** distribution, not a second content stream: Takeaway first sentence (≤ 280 chars) + link, with compliance flags. Fix a bad hook by editing the Takeaway. You post it yourself.
- **How:** `python3 .claude/skills/social-hooks/scripts/hooks.py _posts/<file>`.

### `site-audit` — SEO and technical health
- **Purpose:** crawl a local build for title/description/canonical/heading/image/link/orphan/duplicate/JSON-LD problems and run Lighthouse (mobile + desktop).
- **How:** `scripts/jekyll_build.sh /tmp/site`, `audit_site.py /tmp/site`, then serve and run `lighthouse_run.sh http://localhost:8099/`. `references/gsc.md` explains Search Console statuses ("Crawled – currently not indexed", etc.).
- **Note:** judge Lighthouse on local builds; live runs from the sandbox are distorted by its proxy. It cannot see Search Console: send a screenshot or export.

### `ship` — pre-merge checks, PR, merge, live check
- **Purpose:** the single path to production. Checks → diff read → `TODO.md` → commit → push → PR (only if asked) → merge (only if asked) → verify live.
- **How:** `scripts/ship_check.sh`; after merge `python3 .claude/skills/ship/scripts/verify_live.py /yyyy/mm/dd/slug/ --marker "text"`.
- **Branch convention:** after each merge restart from main (`git fetch -q origin main && git checkout -q -B <branch> origin/main`), push with `--force-with-lease`.

## 4. Agents (`.claude/agents/`)

Agents run in a **fresh context**, so they don't inherit the author's blind spots. Ask for them by name.

### `post-auditor` — independent reviewer (read-only)
- **Purpose:** review posts against `CLAUDE.md` and `write-post/references/audit.md` (compliance, accuracy of interpretation vs the numbers, rules/tax sourcing, style).
- **Use when:** after drafting or editing, before scheduling; always on a new module.
- **Output:** a findings table with severity (P0 breach/wrong direction or rule, P1 misleading/unsourced, P2 style), evidence, and a verdict BLOCK / FIX THEN SHIP / SHIP. It never edits.
- **Try:** "Run post-auditor on `_posts/2026-10-26-up-and-down-capture-ratios.markdown`."

### `post-researcher` — weekly research for future posts
- **Purpose:** find which series are running out of written posts, scan the last 7 days of SEBI/RBI/income-tax/exchange circulars from primary sources, and propose 3–6 teaching topics per series with sources and compliance notes. Writes `_review/research/YYYY-MM-DD.md` and one `TODO.md` row. Research only: it never drafts posts and has no stock or fund views.
- **Use when:** weekly (scheduled), or before `plan-module`.
- **Discovery mode:** also finds *new* topics that could help you show up in search and help retail investors: it maps what the site already owns, looks at what ranks and what is missing (SERP look, regulator and exchange investor material, recent rule changes, seasonal hooks), and sorts each candidate into existing series / new series / standalone / not for this blog. It cannot see search volumes or rankings and says so; paste a Search Console export to give it real signals. Ask for it any time ("run post-researcher in discovery mode"); it also runs automatically when no brief in the last 28 days has a Discovery section.
- **Workflow:** read the brief → pick topics → "run plan-module for <series>, using the research brief" → approve → write.

## 6. Hooks, settings and CI

- `.claude/settings.json` + `.claude/hooks/session-start.sh`: in Claude cloud sessions, installs the Python packages the scripts need (pandas, numpy, pyyaml, matplotlib, pillow, requests). Local sessions: no effect.
- `.github/workflows/pages.yml`: build and deploy; daily rebuild at 09:00 IST publishes posts whose date has arrived (`future: false`). Its `og-cards` job is advisory and must never block publishing.
- `.github/workflows/pr-checks.yml`: on pull requests runs `check_posts.py`, lint on changed posts, OG cards, image dimensions and `jekyll build --future`. Separate from publishing; make it a required check only if you choose to.

### Adding a post by hand (what the skills automate)
1. Pick a slug from `_data/series.yml` for `series:`; name the file `YYYY-MM-DD-slug.markdown`; time ≤ `09:00:00 +0530`.
2. Front matter: `title`, `description` (140–160 chars), `date`, `series`, `image: /assets/og/<slug>.png`, `term` for glossary posts.
3. `python3 scripts/make_og_cards.py`, then `scripts/ship_check.sh`.
4. `{% post_url %}` only to posts dated on or before this one.

## 9. Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Build fails on the post's publish day | A forward `{% post_url %}`; run `scripts/jekyll_build.sh /tmp/s --future` and fix |
| A sentence turns into a list item | A line starts with `2030. ` or a number/Liquid value + `. `; reflow it |
| `og-cards` job red | A title changed; run `python3 scripts/make_og_cards.py` |
| Sandbox fetch of sebi.gov.in resets | `fetch_source.py` retries; if still failing, log a VERIFY row, don't fill from memory |
| Live PageSpeed numbers look bad from the sandbox | Proxy distortion; use `lighthouse_run.sh` on a local build |
| `jekyll: command not found` in cloud | Use `scripts/jekyll_build.sh` |
| A scheduled task says tooling not merged / no repo | Merge the tooling PR; attach the repo to the task |
